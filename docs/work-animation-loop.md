# 💻 工作动画为何回到待机

核查日期：2026-10-09。本机桌面客户端版本：`26.1002.7124.0`。

客户端的动画播放器对非待机动作默认采用有限播放：先播放三轮对应动作，再循环播放第 0 行待机。桌宠按钮调用播放器时没有传入持续循环选项。因而即使任务仍在工作，笔记本画面也可能自动回到待机；用户观察到约两轮后回到待机，与这个有限播放路径一致，实际观察到的轮数尚未通过界面计时复现。

笔记本工作采用第 7 行的六帧，基础时长为 `[120, 120, 120, 120, 120, 220]` 毫秒，一轮 820 毫秒，默认三轮共 2.46 秒。回退后进入六帧待机，待机时长被客户端乘以六，一轮 6.6 秒。仓库中的工作 GIF 设置为无限循环，它是预览文件；桌宠读取 PNG 精灵图，GIF 循环次数不会影响客户端。

核查位置为安装包内的 `webview/assets/app-initial-25361a10f2bf.js`（播放器和动作序列）以及 `webview/assets/avatar-mascot-button-a626ddede376.js`（桌宠按钮调用）。只读取了安装包，未修改客户端。当前 Pets 更新接口可更换名称、描述和精灵图，没有循环次数或状态调度参数。

持续笔记本动画需要客户端在 `running` 状态下开启播放器的持续循环，并在任务状态改变时切换动作。本次已修整素材的待机衔接，但这项客户端行为仍待修复。核查数据见 [报告](../qa/work-animation-runtime.json)。
